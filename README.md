## Jak poruszać się po bazie

1. Wybierz aspekt z mapy wiedzy poniżej i otwórz odpowiadający mu plik.
2. Skorzystaj z nagłówków w wybranym pliku, aby przejść do konkretnego tematu.
3. Linki „Źródła” prowadzą do standardów i materiałów źródłowych. W razie wątpliwości sprawdź tam pełne brzmienie kryterium oraz jego wyjątki.
4. Zacznij od dostępności i użyteczności podczas planowania, a następnie sprawdź treść, responsywność i wydajność. Na końcu skorzystaj z list kontrolnych.

## Jak czytać wytyczne

- **WCAG** oznacza testowalne kryterium standardu. Przy kryterium podano poziom zgodności (A, AA lub AAA); sprawdź pełny opis i wyjątki w źródle.
- **Dobra praktyka** to zalecenie projektowe, które może poprawić doświadczenie, ale samo w sobie nie przesądza o zgodności ze standardem.
- **Wartości progowe** (np. Core Web Vitals) należy interpretować z warunkami pomiaru podanymi w odpowiednim rozdziale.

## Szybka ścieżka przeglądu strony

1. Wybierz kluczowe zadanie użytkownika i przejdź je od początku do końca.
2. Powtórz zadanie samą klawiaturą; sprawdź widoczny fokus i komunikaty.
3. Sprawdź formularze, kontrast, teksty alternatywne oraz strukturę nagłówków.
4. Sprawdź widok mobilny, szerokość 320 CSS px i powiększenie treści.
5. Zmierz Core Web Vitals, jeśli masz dane terenowe, i uzupełnij przegląd testem z użytkownikami.

Baza jest przewodnikiem projektowym. Nie zastępuje pełnej oceny zgodności, testów z użytkownikami ani analizy wymagań prawnych.
